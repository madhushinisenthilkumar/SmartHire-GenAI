# Entry-Level Software Engineer Roadmap

## Core skills needed
- One language deeply (Python, Java, or JavaScript are the most commonly requested for entry-level roles)
- Data structures & algorithms — arrays, hash maps, trees, basic sorting/searching — this is what most interviews test
- Git and GitHub — version control is assumed baseline knowledge
- Basic understanding of how the web works if targeting web roles (HTTP, REST APIs, databases)

## Typical path
1. Pick one language and build fluency before spreading across many.
2. Build 2-3 substantial projects (not tutorials followed step-by-step) — something with a database, an API, or a real user-facing feature.
3. Practice data structures & algorithms problems consistently (30-60 min/day is more effective than cramming).
4. Contribute to a small open-source project if possible — it's a strong, verifiable signal for entry-level candidates who lack work history.

## Common mistakes
- Listing many frameworks/languages on a resume with only surface familiarity in each — depth beats breadth for entry-level.
- Projects that are copies of well-known tutorials (to-do apps, weather apps) without a unique twist or added complexity.
- Skipping DSA practice and hoping project experience alone will pass interviews — most entry-level interviews still test DSA directly.

## Interview focus areas
- Live coding (DSA-style problems)
- System design is usually light or absent at true entry-level, but expect "how would you improve this small system" style questions
- Behavioral questions about teamwork and handling disagreement in code review
